# Что нужно для `LinqDetector`

Сейчас `worker/app/detector/linq.py` — заглушка: `infer` бросает `NotImplementedError`. Сервис работает через `OnnxDetector` (onnxruntime, видеокарта или процессор). Этот документ описывает, что нужно сделать и что нужно получить, чтобы инференс пошёл на ускорителе LinQ.

У меня не было ни ускорителя, ни его SDK, ни документации к нему. Поэтому ниже нет ни одного вызова API LinQ: всё, что касается самого ускорителя, сформулировано как вопросы к поставщику. Остальное проверено на работающем коде.

## Что меняется, а что нет

Меняется один файл: `worker/app/detector/linq.py`. Интерфейс детектора — единственная граница между сервисом и железом:

```python
class Detector(Protocol):
    name: str
    device: str  # попадает в /api/stats и на панель производительности

    def infer(self, model: str, batch: np.ndarray) -> np.ndarray:
        """batch: float32 [N,3,640,640], RGB, 0..1. Возврат: float32 [N, 4+nc, 8400]."""
```

Не меняется ничего вокруг: чтение камер, letterbox, декодирование выхода, пороги, NMS, трекинг, правила, события. Вся пред- и постобработка идёт на процессоре вне детектора (`worker/app/postprocess.py`).

Включение: `worker.detector: linq` в `config.yaml`.

## Что детектор получает и что обязан вернуть

| | `ppe` | `hazard` |
|---|---|---|
| файл | `models/ppe/best.onnx` | `models/hazard/best.onnx` |
| вход | `images`, float32 `[1, 3, 640, 640]`, NCHW, RGB, значения 0..1 | то же |
| выход | `output0`, float32 `[1, 11, 8400]` | `output0`, float32 `[1, 7, 8400]` |
| классов | 7 | 3 |

- ONNX статичный, batch 1. Именно этот файл оставлен для LinQ; `best.dynamic.onnx` рядом нужен только onnxruntime.
- Строки выхода 0–3: `cx, cy, w, h` в пикселях входа 640. Дальше по строке на класс: оценка уже после сигмоиды, отдельной objectness нет.
- NMS в модель не включён, он делается в сервисе. Порог IoU и пороги по классам лежат в `model.yaml`.
- Точные формы входа и выхода, имена тензоров и список классов сервис читает из `model.yaml` (`worker/app/model_spec.py`), в коде их нет.

Если ускоритель возвращает выход в другом виде (квантованный, другой порядок осей, несколько голов без склейки), приведение к `[N, 4+nc, 8400]` float32 делается внутри `LinqDetector`, а не в постобработке.

## Что нужно сделать

1. **Скомпилировать обе модели под ускоритель** из `best.onnx` инструментами LinQ. Результат положить рядом: `models/ppe/` и `models/hazard/`.
2. **Реализовать `LinqDetector`**: в `__init__` загрузить обе скомпилированные модели, в `infer` прогнать батч и вернуть массив нужной формы. Образец структуры — `onnx_detector.py`.
3. **Батч.** Воркер подаёт в `infer` до N кадров за вызов (по кадру с каждой камеры, плюс вырезки). Метод `batch_limit(model)` говорит воркеру, сколько кадров детектор берёт за раз; заглушка отвечает 1, тогда воркер вызывает `infer` по одному кадру. Если ускоритель умеет батч или несколько потоков, это задаётся здесь.
4. **Отказ ускорителя не должен быть тихим.** Ошибка загрузки модели — исключение при старте с понятным текстом. Деградация (например, откат на процессор) — строка в `self.warnings`: она попадает в `/api/stats`, `/api/health` и в жёлтую полосу интерфейса, как сейчас для onnxruntime на CPU.
5. **Проверить совпадение с эталоном** (ниже).
6. **Замерить**: `python -m worker.app.check_device` покажет миллисекунды на кадр, `scripts/bench.py` — сколько потоков держит сервис.

## Как проверить, что детектор считает то же самое

В репозитории есть эталонный тест `worker/tests/test_reference.py`: на 20 картинках из `css test` рамки после постобработки сервиса сравниваются с результатом `ultralytics` на `best.pt` (то же число рамок по классам, IoU парных рамок не ниже 0,9). Сейчас он идёт через `OnnxDetector`. Для LinQ нужно добавить такой же прогон через `LinqDetector` с отдельным маркером pytest (например, `linq`), чтобы обычный `pytest` его не запускал.

Если модель для ускорителя квантуется в int8, точное совпадение не получится. Тогда критерий другой: прогнать тестовую выборку и сравнить mAP и подобранные пороги с цифрами из `REPORT_TRAINING.md`. Пороги по классам в `model.yaml` подобраны для float-модели; после квантования их, скорее всего, придётся подобрать заново тем же скриптом из папки обучения. Это решение за заказчиком: папку обучения сервис только читает.

## Что нужно получить от поставщика LinQ

Без ответов на эти вопросы писать код бессмысленно:

1. SDK или рантайм для Python 3.12: как ставится, под какие ОС (сервис разрабатывается на Windows, упаковка в Docker на Linux).
2. Инструмент компиляции ONNX: какие версии opset принимает (модели экспортированы `ultralytics 8.4.164`, YOLOv8s), все ли операции YOLOv8 поддерживаются, нужна ли замена отдельных слоёв.
3. Нужна ли квантизация. Если да — какой калибровочный набор нужен и какое падение точности типично для YOLOv8.
4. Формат входа: принимает ли ускоритель float32 NCHW 0..1 или ему нужен uint8 NHWC. Во втором случае предобработку можно упростить: `preprocess` в `postprocess.py` отдаёт float32, перевод обратно делается в детекторе.
5. Батч и параллельность: размер батча, можно ли держать две модели загруженными одновременно, можно ли вызывать инференс из нескольких потоков.
6. Пропускная способность на YOLOv8s 640×640: от неё зависит число камер. Для сравнения: RTX 3060 через onnxruntime даёт около 7 мс на кадр в пачке по 4, сервис держит 8 потоков 1080p при 6 кадрах в секунду на камеру, и упирается при этом в процессор, а не в видеокарту.
7. Как ускоритель подключается к машине и виден ли он из контейнера Docker.

## Что учесть в сервисе

- **Вырезки.** Сигарета ищется моделью `hazard` на вырезках людей (до 6 на камеру в секунду, только для людей в зонах с горючими материалами). Если инференс на ускорителе медленнее, чем на видеокарте, первым делом уменьшается `crop_pass.cigarette.max_per_tick` в `config.yaml`.
- **Частота.** `ppe_fps` и `hazard_fps` в `config.yaml`. Если детектор не успевает, кадры пропускаются, очередь не растёт; фактическая частота видна на панели производительности.
- **Процессор.** На восьми потоках узкое место — однопоточный главный цикл воркера (декодирование, предобработка, правила), а не инференс. Быстрый ускоритель сам по себе число камер не увеличит.
